# Risk & Ethics Analysis — Instant Job Estimate

## 1. System Overview
Estimates are generated by **Google Gemini 2.5 Flash Lite**, called directly from the browser with a system prompt grounded in Akbar & Sons' actual brands, product categories, and illustrative PKR price bands. The model returns structured JSON — either an itemized estimate or a flag that the request needs in-store consultation. This is a real AI system, not rule-based keyword matching, and its behavior is documented in full in `AI_USAGE.md`.

## 2. Known Risks & Limitations

| Risk | Description | Mitigation |
|---|---|---|
| Inaccurate estimate | Price bands are illustrative, hard-coded in the prompt — not live stock or pricing | Mandatory disclaimer on every result; final pricing always confirmed in-store |
| Vague/incomplete input | Short or unclear descriptions ("something's wrong with my pipes") don't give the model enough to estimate responsibly | Model is instructed to return `needs_consultation: true` rather than guess |
| Multi-job input silently answered as one job | Confirmed during evaluation testing (Case 12) — a long, detailed description covering 3 unrelated jobs was answered as a single estimate | Fixed: prompt now explicitly states detail does not resolve ambiguity, names this as a critical failure, includes a worked example. Retested and passing — see `evaluation.md` |
| Out-of-scope requests | Electrical, structural, or non-plumbing work could be estimated inappropriately | Explicitly routed to `needs_consultation` rather than estimated |
| False confidence | A displayed price range could be mistaken for a firm quote | `confidence` (high/low) rating shown per estimate, plus a persistent disclaimer in the UI and footer |
| Prompt-following is probabilistic, not guaranteed | An unusual phrasing could still slip past the ambiguity/scope rules since this depends on the model following instructions, not deterministic code | Evaluation sheet (10+ cases) used to catch and fix gaps; this remains a known limitation, not a solved problem |

## 3. Mitigations Implemented
- Every estimate result displays a `confidence` badge (high/low) based on how much detail was given
- A fixed disclaimer — *"Estimate only — confirm exact pricing, stock, and brand availability in-store"* — is included in every non-fallback result, plus a general disclaimer in the page footer
- Vague, multi-job, or out-of-scope input triggers a clear fallback message directing the customer to visit or call the store, instead of a guessed number

## 4. Fallback & Human Review
- When the model determines a request is too vague, mixed, or out of scope, it returns `needs_consultation: true` with a specific reason — the UI shows this as a fallback card, not an estimate
- The shopkeeper remains the final authority on real pricing, stock availability, and any job the AI defers — this AI is a first-pass reference, not a replacement for the manual process
- There is no automated purchasing or commitment step — every estimate is a starting point for a human conversation, matching the actual current workflow described in `validation-notes.md`

## 5. Ethical Considerations
- **Honesty**: Both the UI (disclaimer, confidence badge) and the docs (`AI_USAGE.md`) are explicit that this is an AI-generated estimate with known limitations, not a certified quote
- **Harm avoidance**: A wrong or overconfident estimate could cause a customer to under-budget for a job; the disclaimer, confidence flag, and in-store confirmation step exist specifically to reduce this
- **No manipulation**: Price bands reflect the store's actual product context and are not inflated or structured to drive any particular outcome
- **Scope discipline**: The system is explicitly told to defer rather than estimate outside plumbing/sanitary work, rather than attempting to answer everything

## 7. Planned Improvements
- Replace static price bands with real-time stock/pricing
- Add a staff review step before an AI estimate is shown to a customer, for a future production version
- Expand and continue evaluation testing as new edge cases are found (ongoing process, not a one-time check)
