# Risk & Ethics Analysis — Instant Job Estimate

## 1. System Overview
The estimate is generated by rule-based logic (keyword/pattern matching on the 
user's text description mapped to pricing rules), not a trained AI/ML model. 
This is disclosed here for transparency, as the assignment quality bar requires 
honest evaluation of what the system actually does.

## 2. Known Risks & Limitations

| Risk | Description | Likelihood/Impact |
|---|---|---|
| Inaccurate estimates | Free-text input is ambiguous; rule-matching can miss job details or misclassify job type, leading to under/over-estimates | High likelihood, Medium impact |
| Vague/incomplete input | Users may write short, unclear descriptions ("fix pipe") that don't map cleanly to any rule | High likelihood, Medium impact |
| False confidence | Presenting a number as an "estimate" may make users treat it as a firm quote | Medium likelihood, Medium impact |
| No context for edge cases | Unusual/complex jobs outside the rule set get a generic or default estimate rather than a flagged "unknown" | Medium likelihood, Medium impact |
| No real AI reasoning | Rule-based logic cannot generalize to new phrasing/job types the way a trained model could | High likelihood, Low-Medium impact |

## 4. Fallback & Human Review
- When the rule engine can't confidently match input, the product should not 
  silently guess — it should either ask a clarifying question or clearly flag 
  low confidence to the user.
- No human-in-the-loop review exists in this MVP since it's fully automated 
  and client-side; this is a stated limitation, not a hidden gap.

## 5. Ethical Considerations
- **Honesty**: The system does not use AI/ML in this version. This is stated 
  plainly rather than implied, per the assignment's requirement that AI output 
  limitations be communicated honestly.
- **Harm avoidance**: A wrong estimate could cause a user to under-budget for 
  a job. The "estimate, not quote" framing exists to reduce this harm.
- **No manipulation**: Pricing logic doesn't inflate estimates to drive 
  conversions or hide costs.

## 6. Planned Improvements
- Replace/augment rule-based logic with a real model (e.g. lightweight 
  classifier or LLM-based estimation) to handle more varied phrasing.
- Add explicit low-confidence flagging instead of always returning a number.
- Add a short human-review step before showing final numbers, if this becomes 
  a real product.
